# SQL Problem-Solving Practice Lab

A practical repository for daily SQL problem solving, debugging, and learning notes. This workspace is organized to help me work through 79 interview-style SQL questions with honest progress tracking, reflection, and reusable patterns.

## Why this repository exists

This repository exists to turn SQL practice into a consistent habit. The goal is not to collect polished answers only, but to document the process of understanding a problem, attempting a solution, testing it, fixing mistakes, and recording what was learned.

The repository complements my Notion tracker by storing the actual technical work: queries, attempts, notes, and patterns.

## How to use this repository

1. Open the problem in Notion.
2. Read the original statement and identify the required output.
3. Write your own attempt in the problem SQL file.
4. Test the query in a SQL editor or database environment.
5. Keep the first attempt visible so the learning trail is honest.
6. Write the final working query in the final solution section.
7. Add a concise reflection in the notes file.
8. Update the Notion tracker to reflect progress and next steps.

## Files in each problem folder

Each `SQLXX/` folder contains:

- `solution.sql`: where the problem metadata, first attempt, final solution, and learning notes live
- `notes.md`: a short reflection on approach, mistakes, stuck points, and understanding

The actual problem statements and source URLs remain blank until they are verified from the original source material. No invented company names, URLs, or fake data are added.

## Practice principles

- Understand the logic before you optimize the query.
- Keep notes about mistakes and failed attempts.
- Different SQL dialects may vary in syntax and functions.
- Record the database dialect when known.
- Prefer clarity and correctness over cleverness.
- Learn from each query rather than copying a solution.

## Notion and GitHub workflow

Notion remains the daily tracker for progress and scheduling. GitHub stores the actual SQL work and learning record. Together they form a complete practice loop:

- Notion: daily planning and status
- GitHub: technical execution and reflection

## SQL tools

Use any SQL editor that supports your target database dialect, such as:

- PostgreSQL: pgAdmin, DBeaver, psql
- MySQL: MySQL Workbench, DBeaver
- SQL Server: SSMS, Azure Data Studio
- SQLite: DB Browser for SQLite, DBeaver
